# MoveToMonitorButton 0.1.6 の構造と検証範囲

## 構造

C++17、MSVC、公式Windows SDKを使うWin32アプリです。`main.cpp`は引数解析と起動、`Application`は自分のウィンドウ・フック・トレイと操作状態を所有します。対象アプリのHWNDは借用であり、破棄しません。`WM_NCCREATE`のthisを`GWLP_USERDATA`に関連づけてコールバックをインスタンスへ接続します。コンテキスト引数のない`SetWinEventHook`だけは、UIスレッドの接続先として`thread_local Application*`を使い、終了時に解除します。

`placement.cpp`は候補を調べ、`PlacementResult`として`optional<RECT>`と`PlacementDiagnosis`を返します。候補探索の状態は呼び出し単位で閉じ、診断用の共有変数に結果を書きません。日本語への整形は`diagnostics.cpp`です。座標計算はWindowsに依存しない`layout.hpp`に分離しています。

`MoveOperation`と`MoveStage`は、Idle、WaitingForRestore、WaitingForPosition、WaitingForDpiSettle、WaitingForMaximizeで移動を表します。復元、配置、DPI変更後の再適用、再最大化という順序、80／120／80msの待機、段階ごとの2秒上限、失敗時のWINDOWPLACEMENT復元は0.1.5から変更していません。

`win32_helpers.hpp`は所有リソースとスコープ管理に限定した補助です。標準unique_ptrとSDK解放関数でHANDLE、HWND、HMENU、フック、ペン、CommandLineToArgvWの配列を解放します。描画終了・GDI選択復元・一時フラグ復元もスコープに対応させます。借用の対象HWND、共有アイコン、ストックオブジェクト、システムブラシは破棄しません。Windowsコールバックの境界からC++例外を外へ伝播させません。

## 個別ボタンの実測

`WM_GETTITLEBARINFOEX`を20ms上限で送り、個別の画面座標矩形を取得します。メッセージのLRESULTが0でも失敗とは限りません。非表示・画面外・過大な矩形を除外し、DWMのボタン群範囲とも照合します。使用不可でも見えているボタンは寸法基準にできます。ヘルプボタンは除外領域に含めます。

最小化、最大化、閉じるの順で利用可能な基準を選び、その幅・高さ・上下位置と隣接間隔を使います。画面座標の実測値を二重にDPI拡大しません。同寸法の候補を最大4個試し、置けない場合は従来の通常／小型候補へ戻します。DWMの除外領域を優先するため、アクセシビリティ矩形とDWM矩形に差があると横の余白が完全一致しない場合があります。

実測値が得られない場合に、アプリ名による例外や位置推定を自動で有効にすることはありません。従来の入力先確認を使います。明示的な位置推定は引き続きウィンドウ単位・起動中のみの設定です。

## 入力先と上端の扱い

WindowFromPointで各候補の5点の入力先を取得し、対象との所属関係を検証してヒットテストします。子のHTCLIENTを親の肯定で上書きせず、アクセス拒否・タイムアウト時にも強制表示しません。探索は75ms／160照会、個別ヒットテストは20msを上限とします。

通常／小型候補は5点すべてHTCAPTIONを要求します。実測サイズの候補だけは、上側2点について、対象のトップレベルHWND自身が返すHTTOPを追加で許容します。非最大化・サイズ変更可能であり、GetSystemMetricsForDpiの上枠＋パディングの範囲内に限ります。中央／下側3点、子入力ウィンドウ、HTCLIENT、コーナー、照会失敗には適用しません。

これは実Windowsで観測した境界への対応です。Windows Server 2022の標準Win32ウィンドウでは最小化ボタンが47×30ピクセル、隣の候補の上端がHTTOP、中央と下端がHTCAPTIONでした。全域をHTCLIENT／HTTOP／HTTOPLEFTに変えた実ウィンドウの拒否試験も行い、標準ボタン情報だけで安全と判断しないことを検査します。

追加ボタンの四角い領域は上端も含めてクリック対象です。その区画では上枠リサイズより移動ボタンを優先し、区画外の上枠は変更しません。

## 外観

`caption_appearance.cpp`に色照会、合成用ピクセル生成、UpdateLayeredWindowを分離しています。WS_EX_TRANSPARENTは使いません。通常時はalpha=1/255のほぼ透明な背景を残し、矩形全体のクリック領域を確保します。alpha=0では下のアプリへクリックが通るためです。元のタイトルバーを単色で塗りつぶさず、その上にモニター移動記号と控えめなホバー／押下の陰影を合成します。

前面の基準ボタンの左右余白にある5点だけのRGBから、白または黒の記号色を選びます。タイトル文字やクライアント内容は読みません。カーソルが基準ボタン上にある場合、別ウィンドウが覆う場合、対象が前面でなくなった場合は取り込みません。色情報を画像として保存・送信せず、以前の別対象の色も流用しません。取得できない場合は公開UxTheme／システム色を使い、ハイコントラストでは不透明なシステム色を優先します。

公開UxThemeは対象DWMの全描画状態を複製するものではありません。WP_MINBUTTONには最小化記号が含まれ、DTBG_OMITCONTENTはimagefileテーマの記号を自由に消す機能ではありません。そのため最小化記号を誤って重ねず、移動記号を独自に描きます。Micaや標準ボタンのアニメーションを再実装・完全複製するものではありません。通常背景にも1/255の合成があるため、元の全ピクセルと厳密に同一という意味ではありません。

## 検証

Windowsのcaption_style_testは実SDK／GDIによる100・125・150・200%相当の画像生成、明暗パレット、押下／ホバー、アルファ値を検査します。これらのDPI画像試験は実モニターのDPI切替とは別です。さらに標準Win32のテストウィンドウを作り、配布対象EXEを別プロセスで起動して、実測矩形との一致、透過背景の隅のヒットテスト、タイマー更新後の表示維持を確認します。テストウィンドウの上部だけをBMPで記録します。製品の色照会には画像保存の処理を含めません。

Release／Debugの両方で、上記、座標計算、SDK ABI、SDK補助関数／所有権、EXEローダー、通常起動・UI応答・正常終了を試験します。Linuxでは同じ制御実装を別翻訳単位としてAPI doublesとコンパイルし、ASan／UBSan付き回帰試験を行います。Linuxのappearance_stubは描画を検証するものではありません。製品は公式SDKだけを使い、テスト用のWin32宣言をリンクしません。

Windows Server 2022上の標準フレームでの実行と、Windows 11のExplorer／Mica／各種独自タイトルバー、実モニター間のクリック移動は別の検証です。CIの成功だけで、すべてのアプリ・テーマ・DPI・モニター構成で外観と動作が完全一致すると扱いません。
