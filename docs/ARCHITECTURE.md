# 0.1.8 の構造

## 責務

| ファイル | 担当 |
|---|---|
| `main.cpp` | SDKによる引数解析、Applicationの生成と起動 |
| `app.hpp` / `app.cpp` | 所有状態、前面ボタン、イベント、メニュー、移動状態機械 |
| `inactive_buttons.hpp` / `inactive_buttons.cpp` | 見えている非アクティブ対象と、その独立したボタンの寿命・重なり順 |
| `placement.hpp` / `placement.cpp` | 対象と入力先の検査、配置結果と診断値の算出 |
| `caption_appearance.*` | 基準ボタンの色の参照とアルファ描画 |
| `diagnostics.cpp` | 診断値を日本語表示へ変換 |
| `win32_helpers.hpp` | 所有リソース、一時フラグ、描画スコープ |
| `layout.hpp` | Windowsに依存しない座標計算 |

C++17とWin32 SDKを継続する。Win32の型・コールバック・メッセージのswitchを残し、全APIを独自ラッパーで覆わない。文字列とコンテナーは標準ライブラリを使う。

## 所有権とコールバック

`Application`が状態を所有し、`WM_NCCREATE`と`GWLP_USERDATA`でインスタンスへイベントを渡す。コンテキスト引数のないOUTOFCONTEXTのWinEventだけ、設置したUIスレッドの接続先をthread_localに保持する。対象アプリのHWNDは借用であり破棄しない。自分のウィンドウ、HANDLE、メニュー、フック等はSDKの解放関数をdeleterにしたunique_ptrで所有する。

`InactiveButtons`の各Buttonは安定したアドレスを持ち、そのボタン固有の対象Identityを保持する。イベント中は隠す／無効にするだけで、再入可能なコールバック中にButtonを消去しない。次のrefreshで不要な状態を回収する。WM_NCDESTROYでは参照を切り、再利用されたHWNDが古い対象を引き継がないようにする。

## 非アクティブ表示

表示対象の選別は前面用と共通。タイトルバーがあり、表示・有効状態で、最小化・cloaked・除外・自プロセスでない対象を列挙する。候補上の実際の入力先を確認するため、覆われている場所を無条件に採用しない。

背景用ボタンは自プロセスの所有者なし・非アクティブ化・レイヤー付きポップアップ。対象の直上、他の上位ウィンドウより下へ置く。対象がtopmostから通常へ戻る場合はボタンも降格する。対象のowner、style、入力キュー、ウィンドウプロシージャには手を加えない。

WM_MOUSEACTIVATEはMA_NOACTIVATE。ホバーや最初の押下で対象を勝手に前面にせず、左ボタンを離したときにそのButtonの対象を既存のmove_nextへ渡す。右クリックも同じ対象で既存メニューを開く。移動時の前面化は明示的な操作の結果として既存手順に従う。

候補は最大128件、列挙は最大4096ウィンドウ。同じ対象の探索には既存の75ms／160照会と各メッセージ20msの制限を使い、背景refresh全体も100msを超えたら次回へ回す。境界で開始した処理により厳密な100ms以内ではない。全対象へ毎回重い処理を集中しないよう巡回する。

## 配置と描画

`PlacementResult`はoptionalの矩形と診断値をまとめて返す。WM_GETTITLEBARINFOEXの個別矩形を検証し、幅・高さ・縦位置を優先する。0.1.7で追加した、同じ子の上端リサイズ帯の限定許可と、最大化時の不可視枠差の検証を維持する。HTCLIENTや別プロセスを無条件に許可しない。

余白が足りない場合は小型の縦中央候補を先に検査し、従来の上下探索を残す。アプリ名による例外は設けない。必要な条件は[Explorerの寸法修正](EXPLORER-SIZING-FIX.md)を参照。

背景をほぼ透かした自分の記号だけを描く。色を参照する5点は標準ボタンの余白であり、毎回入力先が対象に属することを確認する。非アクティブな対象でも同じ検査を行い、他アプリの画面をサンプルにしない。画像やタイトルは記録しない。WindowsコールバックからC++例外を伝播させず、失敗は終了経路へ接続する。

## 検証と公開の境界

Windowsの実SDK試験とAPIダブル試験を区別する。Linuxでは非アクティブのWindows描画実装をstubにし、Windows側の実EXE試験で検証する。前面の実アプリ描画36ケースと、非アクティブの2ウィンドウ統合試験は別の試験である。

配布EXEをWindowsで一度ビルドし、両Serverの試験へ渡す。結果のコミットとEXEのハッシュが一致し、必須ケースとSDK／回帰ジョブが成功するまで公開しない。GitHub Releasesへの書き込み権限はmainの公開ジョブだけに限定し、公開前にアップロードを再取得して検証する。PRからリリース公開は行わない。

1画面のCIは物理複数モニターの移動・混在DPI・Windows 11 Store系まで保証しない。Windows 11 Armの画面取得問題はIssue #2で独立して追跡する。
