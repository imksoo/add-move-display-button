# 0.1.5 の構造と変更範囲

## 方針

目的は、動作確認された0.1.4の判定・移動条件を維持しつつ、アプリの本質を読みやすくすることです。Win32を別フレームワークへ移植する変更ではありません。C++17を維持し、継承階層や全APIの独自ラッパーは追加していません。

## 状態と結果の所有

`Application`が自分のウィンドウ、トレイ、フック、対象ウィンドウの識別情報、モニター一覧、操作中の状態を所有します。メンバー関数はその状態を扱い、別インスタンスのモデルとは共有しません。`WM_NCCREATE`で渡された`this`を`GWLP_USERDATA`に関連付け、Win32コールバックをインスタンスへ接続します。

`SetWinEventHook`には利用者コンテキストを渡す引数がないため、設置したUIスレッドのコールバック接続用に限り、`thread_local Application*`を1つ残しています。これはモデルの保存場所ではなく、終了時に解除する接続先です。OUTOFCONTEXT方式を維持しています。

`find_button_placement`は対象と`PlacementContext`を受け取り、`PlacementResult`を返します。配置の有無は`optional<RECT>`、不採用理由と観測値は`PlacementDiagnosis`にまとまります。出力引数と共有診断変数へ別々に書く方式は廃止しました。候補探索用の状態は呼び出しごとの`PlacementSearch`に閉じています。

診断理由は`PlacementReason`で表し、日本語への変換は`diagnostics.cpp`だけが担当します。プロセス昇格情報も`ElevationQuery`として値と照会エラーをまとめて返します。

移動操作は`MoveOperation`と`MoveStage`にまとまり、`Idle`、`WaitingForRestore`、`WaitingForPosition`、`WaitingForDpiSettle`、`WaitingForMaximize`で段階を表します。元のタイマー駆動方式は変更していません。

## SDK・標準ライブラリの利用

| 以前の処理 | 0.1.5 |
|---|---|
| リソースIDの二重キャスト | `MAKEINTRESOURCEW` |
| 手書きのコマンドライン走査 | `CommandLineToArgvW`と`LocalFree` |
| 固定長文字配列への手書きコピー | `StringCchCopyW`と`_countof` |
| 整数の桁分解や診断文字列の連結 | `std::wstring`、`std::to_wstring`、ストリーム |
| 座標のビット詰め、イベントの下位ワード抽出 | `MAKELPARAM`、`LOWORD` |
| 矩形の比較・平行移動・点の包含確認 | `EqualRect`、`OffsetRect`、`PtInRect` |
| システム色のブラシを毎回生成・削除 | 借用の`GetSysColorBrush` |
| 手書きの安定挿入ソート | `std::stable_sort` |

`win32_helpers.hpp`は所有権に関する小さな補助だけを置きます。`std::unique_ptr`にSDKの解放関数を組み合わせ、所有するHANDLE、HWND、HMENU、フック、ペン、引数配列をスコープで解放します。借用する他アプリのHWND、共有アイコン、ストックオブジェクト、システムブラシは破棄しません。

描画開始／終了とGDI選択の復元はスコープで対応させます。一時的な入力透過・再入防止・メニュー状態も`ScopedFlag`で元に戻します。WindowsコールバックからC++例外が外へ伝播しないよう、境界で終了処理へ接続しています。

## 維持する条件

前面ウィンドウ1つだけに表示し、通常は2モニター以上で有効にします。入力先ウィンドウを`WindowFromPoint`で解決し、所属関係を検証して、5点が`HTCAPTION`の場合のみ通常配置を採用します。子の`HTCLIENT`を親の肯定で上書きしません。水平候補、コンパクト候補、75ms／160照会の探索制限、20msのヒットテスト上限も維持しています。

標準ボタン範囲を避け、配置対象と作業領域内に置く条件、全画面・操作中・除外対象の扱いも維持しています。位置推定は引き続き明示的なウィンドウ単位の選択だけです。エクスプローラーのアプリ名による特例や永続設定は追加していません。

移動は復元、別モニターへの配置、DPI変更後の1回の再適用、必要な再最大化の順です。80ms／120ms／80msの待機と段階ごとの2秒上限を維持しています。失敗時の`WINDOWPLACEMENT`復元と、画面座標との区別も維持しています。純粋な座標計算の`layout.hpp`は変更していません。

引数解析だけはSDKの引用符規則を採用するため、引用符で囲まれたオプションも正しく認識します。既存オプションの意味は変えず、前方一致で別の名前を誤認識しない条件を試験します。

## 検証の分離

Windowsでは、実SDKによる引数解析、コピーと切り詰め、Unicode診断文、ハンドル・メニュー・ウィンドウの解放、GDI選択復元を追加試験します。既存の公式SDK ABI照合と、配布EXEのローダー・通常起動・応答・正常終了試験を維持します。ReleaseとDebugを別々に実行します。

Linuxでは、同じ製品実装を別翻訳単位でコンパイルし、APIだけを置き換えます。従来の表示・移動の回帰条件を移植し、例外時の一時フラグ復元とインスタンス間の状態分離も試験します。旧実装の関数そのものを取り込む比較用incは削除し、必要な回帰条件を残しました。標準文字列を使うため、ホストのwchar_tを使用します。この宣言群をWindows ABIと見なしていません。

CIのWindows Server 2022での起動成功と、Windows 11のExplorer上での実表示・クリック移動は別の検証です。ソースの整理と回帰試験だけで、すべてのアプリ、DPI、モニター構成の互換性を証明したとは扱いません。

## 0.1.6: 個別寸法と外観

`PlacementSearch::measured_button`は20ms上限のシステムメッセージ`WM_GETTITLEBARINFOEX`で個別矩形を取得します。返却LRESULTの非ゼロは成功条件ではありません。画面座標を二重にDPI拡大せず、非表示・画面外・過大な矩形を拒否し、利用可能ならDWM範囲とも照合します。disabledはinvisibleと区別し、表示されたままなら寸法基準に利用できます。ヘルプボタンも除外領域に含めます。最小化→最大化→閉じるの順で基準にし、最大4個の同寸法候補を試した後、従来の候補へ戻します。5点の入力先確認とアクセス拒否時の非表示は維持します。

`caption_appearance.cpp`に色照会・合成用ピクセル生成・UpdateLayeredWindowを分離しました。`WS_EX_TRANSPARENT`は使いません。通常時alpha=1を残すことはクリック領域確保のためで、完全なalpha=0ではWindowsが下のアプリへクリックを通すためです。前面の基準ボタンだけの5点の色から記号色を決めます。カーソルが基準ボタン上にあるときや別ウィンドウで覆われた場合は色を取り込みません。色の確認は前面と所属関係をチェックし、前の対象の色は流用しません。

公開UxThemeから取れるのはテーマの色等であり、対象DWMの全描画状態ではありません。`WP_MINBUTTON`を丸ごと描くと既存の最小化記号まで含まれます。`DTBG_OMITCONTENT`はborderfill用で、imagefileテーマの任意の記号を消せるAPIではありません。そのため誤った最小化記号を合成せず、元の背景を透かし、独自の移動記号と控えめなホバー／押下の陰影を合成します。Micaの再実装や標準ボタンのアニメーションの完全複製は行いません。

`caption_style_test`はWindows SDK/GDIで描画を試験し、製品EXEを別プロセスで起動して、実Win32フレームとの矩形一致とヒットテストを検証します。CIで作ったテストウィンドウの上部だけをBMPで記録します。これはテスト専用処理で、製品の色照会は画像を保存しません。Linuxの`appearance_stub.cpp`は描画に関して何も証明せず、従来の制御ロジック試験を分離するためだけのものです。
